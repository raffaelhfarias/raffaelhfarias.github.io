Attention

LLMsTransformersFundamentos

O problema que attention resolve

Uma palavra isolada carrega pouca informação. O significado depende do contexto ao redor. Em “depositei dinheiro no banco” e “sentei no banco da praça”, a palavra “banco” precisa olhar para outros tokens para ser interpretada.

Attention permite que cada token considere os outros tokens da sequência e atribua mais peso às partes relevantes. Em vez de tratar o texto apenas como uma sequência que passa de uma posição para a próxima, o modelo calcula relações entre posições.

Analogia: uma pergunta procura informações relevantes. A Query representa o que estou procurando; Keys descrevem o que cada item oferece; Values carregam o conteúdo que será combinado.

Antes da attention: tokens e representações

O texto é dividido em tokens e cada token recebe uma representação numérica. Essa representação não é ainda uma definição completa do significado: ela é atualizada conforme o token interage com o contexto.

  1. O texto é tokenizado.
  2. Cada token recebe um embedding.
  3. Uma informação de posição é adicionada, porque a ordem importa.
  4. Attention mistura informações de diferentes posições.
  5. Camadas posteriores refinam a representação e produzem a saída.

Query, Key e Value

  • Query: representa o que a posição atual precisa encontrar.
  • Key: representa quais características cada posição oferece para comparação.
  • Value: carrega a informação que será agregada depois que a relevância for calculada.

Os três são projeções aprendidas da mesma representação quando usamos self-attention. O modelo aprende quais relações ajudam cada tarefa.

O cálculo em etapas

  1. Calculo a compatibilidade entre cada Query e todas as Keys.
  2. Divido pela raiz da dimensão das Keys para evitar valores grandes demais.
  3. Aplico softmax para transformar as pontuações em pesos.
  4. Faço uma soma ponderada dos Values.
scores = Q @ K.T
scaled_scores = scores / sqrt(d_k)
weights = softmax(scaled_scores)
output = weights @ V

Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V

O resultado de cada posição é uma combinação dos Values. Se uma Key for considerada mais relevante para aquela Query, seu Value recebe mais peso.

Um exemplo pequeno

Considere a frase “O relatório de vendas caiu”. Para interpretar “caiu”, o modelo pode dar mais atenção a “relatório” e “vendas” do que a “O”. A matriz de attention representa essas relações como pesos.

tokens:  O   relatório   de   vendas   caiu
           ↘      ↘              ↗
              contexto de "caiu"

Esse desenho é uma simplificação. Na prática existem várias dimensões, cabeças e camadas, mas a ideia de combinar contexto relevante continua a mesma.

Self-attention e causal mask

Em self-attention, as posições consultam informações da própria sequência. Em um modelo que gera texto da esquerda para a direita, a posição atual não pode olhar para tokens futuros. Uma máscara causal transforma essas posições futuras em pontuações que não participam do softmax.

Isso explica por que o modelo consegue prever o próximo token sem acessar a resposta que ainda deveria produzir.

Multi-head attention

Uma única attention pode aprender um tipo de relação. Multi-head attention divide a representação em cabeças que podem observar relações diferentes: concordância, posição, referência, estrutura ou dependência entre palavras.

Depois, as saídas das cabeças são concatenadas e projetadas novamente. O objetivo não é simplesmente “ter mais attention”, mas permitir que diferentes padrões sejam aprendidos em paralelo.

Cross-attention

Na self-attention, Query, Key e Value vêm da mesma sequência. Na cross-attention, a Query vem de uma sequência e Keys/Values de outra. Isso permite que uma representação consulte outra fonte, como em um decoder olhando para as representações produzidas por um encoder.

Por que isso importa para AI Engineering

Não preciso implementar toda a arquitetura de um Transformer para usar uma LLM, mas entender attention ajuda a raciocinar sobre contexto, tokens, limites de janela, custo e por que informações relevantes podem ser ignoradas quando o contexto fica grande ou mal organizado.

  • Mais tokens significam mais computação e custo.
  • Um contexto maior não garante que todas as partes receberão atenção útil.
  • Chunking e recuperação em RAG ajudam a entregar contexto mais relevante.
  • O modelo não “consulta uma base” automaticamente; a aplicação precisa fornecer o contexto ou uma ferramenta.

  • Como o tamanho do contexto afeta custo e latência?
  • O que muda quando uso múltiplas cabeças de attention?

Conexões desta nota

Attention é um dos fundamentos por trás das LLMs usadas em AI Engineering. Em aplicações de conhecimento, ela ajuda a entender por que a seleção de contexto no RAG é tão importante.
